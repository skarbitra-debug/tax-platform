# B01a.3 — generation и known identity containment

Локальная база: принятый B01a.2 `73c7207b19fa5f49c2ca091783fcb01286528fcf`.

## Контракт

Root принял локальный технический дизайн `CURRENT_SESSION_GENERATION = 1`. Новый код отвергает baseline JWT без sessionGeneration, неверный тип, старое и будущее поколение. Только успешный Credentials signIn может присвоить generation. Refresh/update payload не обновляет старый токен; текущая разрешённая сессия сохраняется. Политика едина для edge и Node и не читает env.

Запрещены ровно нормализованные `realtor.dev@example.com` и `admin@example.com`. Credentials authorize отказывает им до user query/password verify независимо от NODE_ENV/SEED_DEV. Остальные ACTIVE пользователи используют прежний парольный путь, включая dummy verify для неизвестного разрешённого email. Пользовательский input не выбирает role/generation.

Middleware не считает legacy/seed cookie входом и не возвращает её с login домой. requireRole проверяет generation до DB, затем текущие email/status/role/realtorProfile.id одним SELECT. DB errors не разрешают fallback. Role/profile drift отзывает session вместо home redirect loop; согласованные роли сохраняют прежние маршруты. Все numeric cookie chunks двух authjs.session-token prefixes удаляются session-end, чужие cookie остаются. Ответ 303 ведёт только на внутренний login, причина отражается лишь для exact blocked.

## Проверки

```sh
pnpm --filter @tax/web test
pnpm test
pnpm typecheck
pnpm build
pnpm e2e e2e/funnel.spec.ts e2e/session-containment.spec.ts
git diff --check
```

Transport E2E — только отдельный loopback web (`pnpm --filter @tax/web dev --hostname 127.0.0.1`), E2E_WEBSERVER unset, matching PORT/E2E_BASE_URL/APP_URL, AUTH_TRUST_HOST и отдельный синтетический AUTH_SECRET. Тот же тестовый secret передать тесту как E2E_SYNTHETIC_AUTH_SECRET. Генерируются только synthetic encrypted JWT; реальные cookies/пароли не нужны. Prisma generation может требовать synthetic loopback DATABASE_URL; DB server, миграции, seed и настоящий вход не требуются.

E2E проверяет реальный Auth.js session transport: legacy/current seed/expired/wrong-key/malformed cookie → anonymous, current allowed → session; legacy login/admin не образуют цикл. Encoded allowed fixture не доказывает парольный login: authorize отдельно проверен unit тестами. Реальные account/secret mutations отсутствуют. Версии Next/Auth.js не обновлялись; dependency hardening — отдельный пакет.

## Пределы и rollback

После отдельного будущего применения все baseline сессии должны войти заново. Это release-level массовый отзыв, не registry/персональный revoke-all/MFA. Перед применением владелец подтверждает доступный non-synthetic ACTIVE ADMIN и recovery процесс; локальный пакет этого не проверяет и не просит настоящих credentials.

Строки Users/seed не менялись; неизвестные компрометированные identities, прежние права на ПД и прочие security findings не закрыты. D01–D20 не принимаются техническим generation решением. Secret rotation, deployment, remote publication отсутствуют. Старый параллельный deployment продолжает принимать старые JWT; его cutover/остановка принадлежит B01b.

Rollback после будущего применения не должен уменьшать generation или возвращать baseline auth callbacks. Floor сохраняет generation deny, known identity deny, chunk cleanup и ограничения B01a.1/B01a.2. Локальные commits/worktrees сохранены, чужие деревья не очищаются.
