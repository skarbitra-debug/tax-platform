# B02a.1 — CI unit coverage and production build

The `checks` job runs `pnpm test`, whose root script includes every test-bearing workspace package except `@tax/integration-tests`. This includes the web session/legacy containment tests and the inert bot tests, as well as config, crypto and core. The former three-package allowlist omitted web and bot.

An independent `Production build` step runs `pnpm build` after unit tests. Its step-scoped environment contains only explicit synthetic values: a loopback PostgreSQL format placeholder, a synthetic Auth.js key, local APP_URL, host trust, noindex and disabled Next telemetry. This compiles Next and the bot; it does not start either application or require a running database. No deployment job is introduced.

## Local verification contract

- Install the accepted lockfile in an isolated checkout, generate Prisma, then run `pnpm test`.
- To demonstrate discovery, create one new temporary failing Vitest test in web, run the previous allowlist and then `pnpm test`, and remove that exact test. Repeat separately for bot. The old command passes despite each probe; the root command fails with the corresponding marker. Remove both owned probes before the final green run or any commit.
- Run `pnpm build` using the exact synthetic environment from the workflow build step and a clean Node 22 environment.
- Run `pnpm exec prettier .github/workflows/ci.yml --check` and `git diff --check`.
- On a newly created, migrated and seeded synthetic loopback PostgreSQL cluster, run `pnpm test:integration` and `pnpm e2e`. Never borrow an existing DATABASE_URL or production environment.

The separate `db-tests` job retains PostgreSQL 17, migrations/seed, integration tests, Playwright Chromium installation, E2E and failure reports. Its `E2E_SYNTHETIC_AUTH_SECRET` must equal its synthetic `AUTH_SECRET`, with `AUTH_TRUST_HOST` enabled. `E2E_WEBSERVER=1` lets Playwright manage its dev server; this is not production-artifact E2E verification.

## Limits

Local verification is not a GitHub Actions run. The local synthetic database used PostgreSQL 16.14; CI still uses PostgreSQL 17 Alpine, so that platform/version remains to be verified by a separately authorized remote run. No push, deployment, live database change or credential rotation is part of this package.

The existing lint command remains a known no-op pending B02a.2. This change neither supplies a real lint gate nor changes dependencies, application logic, container packaging or the containment rules accepted in B01a.1–3. Existing triggers, read-only permissions and failure behavior are preserved.
